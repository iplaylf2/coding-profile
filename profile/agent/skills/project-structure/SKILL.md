# Project Structure

## Grouping and Growth

- What makes these entries peers at this level? What work does their
  grouping serve, and what distinction lets a reader choose among them?
- What does seeing the entries together in a list help someone do? Which
  entries need to be found or changed independently? Would giving them their
  own units in a directory make that work easier?
- If the current boundaries obscure the responsibilities, how would you group
  the material already here? Where would the next addition suggested by
  current work belong in that grouping?

## Sources and Interfaces

When the same value appears in two places, what sets it in each? Could one
change independently of the other? Give each shared fact one maintained
source in the unit that defines it.

A live view can link to that source or derive its contents from it. If a
record describes a past event, which dated observation or source revision
captures the state it needs?

- If a directory already records which units exist, what does a separate
  index contribute? Which choices about selection or order does it own, and
  which entries would merely have to be kept in sync?
- Through which entry point does a reader or caller find and use the unit?
  What must be visible there, and what can stay inside?
- What knowledge crosses the boundary, and in which direction? If one unit
  changes an internal detail, which other unit would have to change with it?
- What actually establishes a dependency suggested by the directory layout?
  If a chain of dependencies leads back to its starting unit, does the cycle
  interfere with the order in which the units must be ready or understood?
